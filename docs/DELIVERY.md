## 五、本轮最有价值的七个发现

1. **`pnpm ci` 是一条永远为绿的假闸门** —— 它是包管理器的内建 clean-install，会遮蔽同名 script。
   真正的门禁名是 `verify`，并由 `check-gate-entry.ts` 把「门禁的形状」本身变成机器可检的不变量。
2. **`better-sqlite3@13` 要求 Node ≥ 22** —— 工程师实测 Node 20 下直接段错误（ABI 不匹配，不是缺 FTS5）。
3. **验收工具本身必须被验收** —— 三个同族缺陷：抽取正则在 CRLF 文件上匹配不到 ⇒「跑通了但什么都没验」；
   门禁脚本名与文件名映射不一致；守卫只断言「文件存在」而不验行为。每个都补了负控。
4. **门禁只读一份文档 ⇒ 它的覆盖就等于那份文档的覆盖**（F-01）——
   实测「把计划文档的参数分类改回旧口径 ⇒ **6 条门禁全部 exit 0**」。
   ⇒ 凡是「同一规则写在几份文件里」，就要给**几份文件都配守卫**；否则副本就是漂移的温床。
5. **负控自己也可能是真空的**（QA 第四轮推翻了自己第二轮的证据）——
   `intensity()` 的两道钳制在正常输入下**行为等价**，任何「删掉一道」的断言都红不起来。
   ⇒ 判据要落到「它到底是因为什么而失败」；行为层无解时，**静态扫描**才是通用解。
6. ★ **门禁可以「三处自洽」却漏掉整类漂移**（本轮主理人独立发现）——
   合并「C 终裁」后，`src/store/write.ts` 已发出**两个** warning code，
   而**三处白名单全都还只有 `ALIAS_CONFLICT`** ⇒ **门禁仍全绿（EXIT=0）**。
   根因：门禁只做**三方互相比对**（白名单 ↔ 源码常量 ↔ 文档表格），
   **从不去检查「源码里实际发出的 warning code 集合」** ⇒ 新加一个 code 而忘了登记 ⇒ 门禁完全看不见。
   ⇒ 这是 **C36「同一件事不得有两套词」的经典漏洞**：code 有**两处**来源，门禁只保证它们**各自与文档一致**，
   不保证**彼此一致**。
   ⇒ **已修**：新增「源码实发 warning code ⊆ 白名单」守卫 ⇒ **合并当日即在实战中生效**（登记缺失 ⇒ EXIT=1，指名报红）。
7. ★ **「实测了 N 组」这句话必须带上「在哪个域里测的」**（本轮架构师复核 + 主理人独立复现）——
   架构师实测 77 组 `(Δt, τ)` 网格得出「两道钳制互为冗余、删任一道行为不变」⇒ 我独立复现（128 组）**确认**。
   ⚠️ **但那个网格的 `τ` 全是正的** ⇒ 我补测 `τ < 0` 域 ⇒ `Δt=1, τ=-1` 时**删掉 `min` 得 `2.718…`**、
   `Δt=1e6, τ=-1` 得 **`Infinity`** ⇒ **在越界域 `min(1,·)` 是承重的** ⇒
   ⇒ 「互为冗余」只在**生产域**成立 ⇒ **用勘误去替换错误，不能再写一句新的错误**。
   ⇒ **判据：网格设计本身也是判据的一部分**。

### 5.1 本轮固化的方法论（写给下一个接手者）

| # | 纪律 | 出处 |
|---|---|---|
| 1 | **守卫要「能抓住坏的」+「不误伤好的」**：只做前半截的守卫会变成「逼着人用某种写法才能过门禁」⇒ 那是在制造技术债 | 工程师-3 的 `check-clamp`「不误报」用例（中间变量写法 / 内联写法必须放行） |
| 2 | **守卫的判据要抽成可注入的纯函数** ⇒ 负控才能在不污染源码/正文的前提下测它 | 工程师-2 的 warning code 守卫；架构师的 §11.2 名册守卫 |
| 3 | **同一件事有 N 处副本 ⇒ N 处都要有守卫**；只守一处 = 那一处之外全是漂移的温床 | F-01 残余 ①（计划文档侧计数声明） |
| 4 | **转述别人给的探针时要自己把式子算一遍**；探针的**输入**也要自证，不只是**期望值** | QA 第五轮订正（探针 2 的参数与数值不自洽） |
| 5 | **实测要自证域**：「实测了 N 组」必须带「在哪个域里测的」 | 发现 7（τ≥0 vs τ<0） |
| 6 | **加一条门禁必然连带改四处**（写死分母 / 脚本注释 / README / 契约测试）⇒ 这不是越界，是同一件事的四个面 | 本轮 `check:clamp` 落地 |
| 7 | **「边界可以存在，但必须可观测」** ⇒ 一个刻意保留的边界 ⇒ 必须配一条 warning，否则就是静默 | D-3/R2 的 `ALIAS_TARGET_NOT_LINKED` |
