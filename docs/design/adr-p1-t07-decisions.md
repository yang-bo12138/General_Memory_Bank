## 1. D-1 便利查询函数：**保留，但独立**

**裁决**（主理人拍板 ①）：库**可以**提供「按上下文匹配已知实体名」的辅助函数，但

1. **独立**：**不在** recall 流水线里（流水线只做「名字 → id」的归一）；
2. **显式**：只有**调用方主动调**它才算数（调用方自己决定要不要用）；
3. **成本写在脸上**：文档必须写明成本 = **每次调用 O(#实体 + #别名) 行扫描**
   （子串匹配 ⇒ 短名/英文短词会误命中，无词边界）；
4. ⚠️ **阶段 1 不实现它**：它不在 §12 阶段 1 的方法清单里 ⇒ 实现它会把阶段 1 的范围扩到清单之外。

**理由**（与 ADR-2 / 成本模型 / 步骤 0 的耦合三条同源，见 `adr-p1-t08-gaps.md` §1.3）：
摘要是「**别让后人以为它不存在**」——设计稿留口子，实现阶段另议。

## 2. D-2 §9.3.0.1 的措辞：**主理人的读法成立，我的「四项独占」写法已被取代**

**裁决**（B）：§9.3.0.1 首句改成

> **在写入路径内，§4.9 步骤 2 / 3c 的合并写入序列是唯一能改变这六项的代码路径**：
> `content` / `content_hash` / `embedding` / `growStability` 加固 / `content_history` 归档 / `merge` 事件。

**我要认领的一处**：我上一轮（ADR-P1-R2 的 R-5）把它改成了「**四项**（不含 `embedding` 与 `growStability`），
并写「步骤 2 不走合并序列」——**这一点与原文不符**：原文第二段本来就写着
「**前台写入（§4.9 步骤 2 / 3c）**、去重路径、后台补齐扫描全部走它」，
⇒ **步骤 2 本来就在这条路径上**，我的改写把读者引向了一个错误的例外。**已按 D-2 改回，并把六项清单恢复。**

**但我保留一处限定（并写进了正文）**：「**写入路径内**」这四个字不可省——
**`touch()`（§4.2）也加固**，它同样调 `growStability()`。
⇒ 逐字读「唯一能改变这六项的代码路径」而不加限定，就是**假命题**。
⇒ 正确表述是两句：
- 「**写一条记忆时**，正文/向量/稳定度/历史/事件只由合并写入序列改」（本节管这个）；
- 「**稳定度只由 `growStability()` 改**」（§4.2 / §4.15.5 的另一条通则，管 `touch()` 这条路）。

**同时写死的一条实现事实**：`UPDATE memories SET embedding` **全库只应出现在一个模块里**
（当前实现：`src/store/merge.ts`）⇒ 可用**静态扫描**守住；
步骤 2 碰 `embedding` 的唯一入口是「**向量回填**」——**只补 `embedding IS NULL` 的行，已有向量不得覆盖**。

### 10.6 D-13：§11.2 warnings 名册的「**= 方向**」守卫（第三处相等的最后一个方向）

> **触发**：工程师-2 报出「既有守卫只有 ⊆ 一个方向 ⇒ **多出来**的名字不会报红」；
> 主理人核实成立并定判据：「**只比码形态的项**（`/^[A-Z][A-Z0-9_]*$/`），
> 必须**恰好**等于 `EXPECTED_WARNING_ONLY_CASES`（集合相等，不是包含）」。

**① 为什么那一格是「机器读的名册」**（实测，`parseSection11_2Methods` 的第三格解析结果）：

```
parseSection11_2Methods(DESIGN-v2.md).get('warning_only')
  ⇒ ["write", "ALIAS_CONFLICT", "ALIAS_TARGET_NOT_LINKED"]
```

⇒ 第三格里**每一个反引号包住的标识符**都会被收进该组
⇒ **那一格不是散文，是一份名册** ⇒ 散文放进去会变成「名字」，机器读的那一份必须保持干净。

**② 既有守卫的缺口**：

| 方向 | 谁查 | 缺口 |
|---|---|---|
| 脚本白名单 ↔ 源码白名单 | `compareNameSets(EXPECTED_WARNING_ONLY_CASES, WARNING_ONLY_CASES, …)` | ✅ 无 |
| 白名单 ⊆ 文档名册 | 既有逐码循环 | ✅ 无（少一个码就红） |
| **源码实发 ⊆ 白名单** | 工程师-2 的 `checkWarningCodesRegistered` | ✅ 无（**方向相反**：白名单超前于实发**允许**） |
| **文档名册 ⊆ 白名单** | ⚠️ **本轮补上**（D-13） | ⇒ 改前**没有任何守卫** ⇒ 陈旧码名可无成本堆进那一格，而门禁照样绿 |

**③ 判据为什么是「码形态项」而不是全列**：

- 那一列**合法地**含方法名（`write`）⇒ 朴素地判「文档名册 == 白名单」会**恒红**；
- 方法名是**小写开头**、码是**大写开头** ⇒ 按**形态**过滤既准确又不误伤；
- ⚠️ **形态判据不能退化成「出现在白名单里」**（那是循环论证：拿答案去判答案）
  ⇒ 白名单漏了某个码 ⇒ 它会降级成「非码形态」⇒ 门禁反而**看不见**它。
  ⇒ 故用 `/^[A-Z][A-Z0-9_]*$/` 这个**与白名单无关**的形态判据。

**④ 落点**（判定抽成**可注入的纯函数** ⇒ 负控喂假数据，**不改正文**）：

| 函数 | 职责 |
|---|---|
| `isCodeLikeName(name)` | 形态判据（首字母大写 + 只含大写字母/数字/下划线） |
| `extractCodeLikeNames(names)` | 从一列名字里挑出**码形态**项（去重 + 排序）——**纯函数** |
| `checkWarningOnlyRoster(docNames, expected)` | 「= 方向」守卫——**纯函数**，返回不一致清单 |

⚠️ **期望侧不过滤**（只滤文档侧）：期望侧是**权威名单** ⇒ 万一白名单里混进一个非码形态的项，
「缺少」正是**应该报**的信号。

**⑤ 三个方向合起来才闭环**：

```
源码实发  ⊆  白名单  ==  文档名册的码形态项
（工程师-2）      （脚本↔源码）    （本轮补的 D-13）
```

**⑥ 负控**（`tests/contracts/scripts.test.ts`，**只喂假数据，不改 `docs/design/DESIGN-v2.md`**）：

## 12. 两项复核结论（主理人 2026-10-31 派我复核）

### 12.1 F-08 ③：`intensity()` 两道钳制的守卫形态 —— **静态扫描是「形状守卫」；「互为冗余」只在 `τ ≥ 0` 域成立**

**主理人已采纳并已落地的方案**：`scripts/check-clamp.ts` 扫描 `intensity()` 函数体，
确认 `Math.max(0,` 与 `Math.min(1,` **同时存在**（且作用在正确的量上），挂进 `pnpm run verify` 链；含负控。

★ **我的复核结论（已实测；本轮又自我修正一处 —— 主理人复核指出我的措辞过宽）**：

- 现状实现（`src/core/decay.ts`）：
  ```ts
  const elapsedMs = Math.max(0, resolveNow(now) - memory.last_access);  // ① Δt 下钳
  return Math.min(1, Math.exp(-elapsedMs / tauMs));                    // ② 结果上钳
  ```
- **① 在前**：`Δt ≥ 0` ⇒ `exp(-Δt/τ) ≤ 1` ⇒ **② 恒为无操作**；
- **② 在前**：`Δt < 0` ⇒ `exp(-Δt/τ) > 1` ⇒ **② 拉回 1**，与「① 把 `Δt` 归零」的结果**逐位相同**；
  ⇒ **在 `τ ≥ 0` 域**：任一道单独存在都足以保证 `intensity ≤ 1` ⇒ **删掉任一道，不改变任何可观测行为**。
- **实测（生产域）**：77 组 `(Δt, τ)` 网格（`τ` 全为正：负 `Δt` / `Δt = 0` / `Δt/τ = 745、746 天的下溢边界 /
  `τ` 从 1ms 到 1e15ms / `τ = 0 且 Δt = 0` 的 `0/0 = NaN` 边界）⇒ **去掉任一道，0 处差异**（NaN 边界也一致）。
  （主理人用 128 组更密的网格独立复现了同一条结论。）

⚠️⚠️ **域限定（本轮最重要的一条 —— 用勘误换另一个错误，是本项目最忌讳的事）**：
**我上一稿写「删掉任一道，不改变任何可观测行为」——这句话过宽**，因为我的网格里 `τ` 全为正。
- **在 `τ < 0` 域（`stability` 为负的**越界输入**）它不成立**：此时 `exp(-Δt/τ) > 1`
  ⇒ **`min(1, …)` 是唯一拦住越界的那道**（`max(0, Δt)` 归零的是 `Δt`、**不是 `τ`** ⇒ 拦不住）。
- **实测**（主理人提供）：`Δt=1, τ=-1` ⇒ 完整实现得 `1`、删掉 `min` 得 `2.718…`；
  `Δt=1e6, τ=-1` ⇒ 删掉 `min` 得 `Infinity`；`Δt=0, τ=-1` ⇒ 两者都是 `1`（`Δt=0` 时 `max` 已把 `Δt` 归零）。
- ⇒ **两个域必须分开说**：**生产域（`τ ≥ 0`）两道互为冗余**；**越界域（`τ < 0`）`min(1, …)` 承重**。
  ⇒ 这也解释了 F-08 ② 的**负 τ 探针**为什么必须用**越界输入**：生产域内**根本不存在**能区分两道钳制的输入
  （该必要条件已写进 `tests/unit/decay.test.ts` 的注释里）⇒ **越界输入是这条探针的必要条件，不是「不严谨的取值」**。

⇒ **推论三条（均已带域限定）**：
1. ⚠️ **设计稿 §4.1 原句「两重防护缺一不可……缺任一 ⇒ `intensity > 1`」在生产域是错的** ⇒ **已勘误**
   （§4.1 现写成「`τ ≥ 0` 域互为冗余」+ 实测数据 + **`τ < 0` 域的例外** + 两域分述）。
2. ⚠️ **`check-clamp.ts` 是「形状守卫」不是「行为保证」**，且要**按域分述**：
   - **生产域（`τ ≥ 0`）**：它守不住行为（等价改写会绕过它；而按上面的冗余性，它本来也守不住什么）；
   - **越界域（`τ < 0`）**：它与行为探针**互补**（一个钉写法、一个钉行为）。
   ⇒ **不撤它**（它挡「顺手把钳制删了」这类**误改**，负控已证有鉴别力），但文档必须这么标。

  **合法地**含方法名（`write`）⇒ 若硬编码「非码形态项只能是 `write`」，
  将来某个 warning 由别的方法产出（例如 `setAlias`）就会**假红**。
  ⇒ **接受**：那一列的「方法名」部分**不做集合相等**（它不是码名册）。
- ⚠️ **一处事实更正**（工程师-2 报告里的推断有误，在此更正以免被当成依据）：
  「往那一格里塞一个**与抛错组重名**的词（例如 `forget`）⇒ 后面那条
  「`X` 刻意不是异常，却出现在「throw_not_found」的代码名单里」会报红」——**不会**。
  那条守卫查的是**源码侧**的 `METHODS_THROWING_NOT_FOUND` 等常量
  ⇒ 与**文档那一格的内容无关** ⇒ 塞 `forget` 进去是**静默通过**的。
  ⇒ 该守卫的真实作用是「**白名单里的码不许同时被登记成抛错方法**」（防止一个码同时有两套词，C36），
  **不是**「文档那一格不许出现抛错方法名」。两件事不要混。
