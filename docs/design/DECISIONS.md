# 裁决台账（DECISIONS）· 索引

> **本文件是索引，不是台账正文。**
> ⚠️ **它只给指针**（哪条裁决在哪份 ADR 的哪一节）⇒ **正文一律在 ADR 里**。
> ⇒ **理由（C36「同一件事不得有两套词」）**：把裁决正文复制进索引 ⇒ **索引变成第二份真相**
> ⇒ 两份一漂移，读者读到的是**过期的裁决**，而门禁守的是**另一份**。
>
> **怎么用**：① 想知道「某件事裁过没有」⇒ 查 §二 的索引表；② 想知道「裁的是什么」⇒ **按指针打开那份 ADR 的那一节**。
> ⚠️ **历史裁决有过反转** ⇒ **只认「现行有效」那一版**（每份 ADR 的摘要表里标了 ★ 的那条），
> **不要**引用已被取代的旧结论（它们都标了「已被取代」）。

---

## 一、这是什么 / 不是什么

| | |
|---|---|
| **是** | 一张「**裁决 → 落点**」的索引表（指针） |
| **不是** | 裁决的正文（正文在 ADR 里） |
| **不是** | 设计稿（设计契约在 `DESIGN-v2.md`） |
| **不是** | 任务分解（那在 `DEVELOPMENT-PLAN.md`） |

⚠️ **为什么需要它**（P2 收官验收 Q-12）：
阶段 2 之前，`docs/design/` 下**只有 4 份 P1 的 ADR** ⇒ **P2 的所有裁决都没有台账落点**；
而「性能门槛口径」「`mergeMemory` 的设计缺口」「裁决写到哪里」这几条**正需要架构师裁决**
⇒ **连「裁决写到哪里」都没有被指定** ⇒ 本文件就是那个落点。
