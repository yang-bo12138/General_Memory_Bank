# 裁决台账（DECISIONS）· 索引

> **本文件是索引，不是台账正文。**
> ⚠️ **它只给指针**（哪条裁决在哪份 ADR 的哪一节）⇒ **正文一律在 ADR 里**。
> ⇒ **理由（C36「同一件事不得有两套词」）**：把裁决正文复制进索引 ⇒ **索引变成第二份真相**
> ⇒ 两份一漂移，读者读到的是**过期的裁决**，而门禁守的是**另一份**。
>
> **怎么用**：① 想知道「某件事裁过没有」⇒ 查 §二 的索引表；② 想知道「裁的是什么」⇒ **按指针打开那份 ADR 的那一节**。
> ⚠️ **历史裁决有过反转** ⇒ **只认「现行有效」那一版**（每份 ADR 的摘要表里标了 ★ 的那条），
> **不要**引用已被取代的旧结论（它们都标了「已被取代」）。

**裁决摘要 —— 每条都能读出「不这么选的代价」**（正文与完整论证见同稿 §2 对应小节）

| # | 裁决 | ★ **不这么选的代价** |
|---|---|---|
| **D1** | 端口由 `MemoryStore` 在**每次带向量的召回**时**现场装配**，**不缓存**（`setParams()` 就地改 params 容器 ⇒ 缓存 port = 缓存构造时的探针数） | 缓存一个 port ⇒ `setParams({ROUTER_NPROBE_FINE})` 之后 **`route()` 用新探针数、`search()` 内部用构造时的旧值**（IVF 的 `search()` 用 `this.nprobe*`）⇒ **桶集分叉**：召回悄悄少一批候选、**不报错**、**无法复现**（表现为「某些查询莫名其妙召不回」） |
| **D2** | `queryEmbedding` 是**唯一开关**：不传 ⇒ **零影响**（一个字段都不变） | 若「不传」也留一条路径（装配、判定、返回空数组）⇒ 每个既有宿主每次召回都被动改行为，而**全仓库现在没有任何一处传它** ⇒ 83 文件 / 1,757 断言的等价基线不再是证据。**成本维度**：不传时连四态判定的全表 COUNT 都**不发生**（一次实测：不传 **3 条 SQL / COUNT 0 次**，传了 **6 条 / COUNT 1 次**）⇒ 无条件装配 = 给每次召回加一次百万级全表计数，且**测不出来** |
| **D3** | 闸门三段**顺序写死**：时间窗随 `filter` 进 `search()` → ② cos 阈值（低于它**不进候选**，不是得 0 分）→ ③ 强度精筛 → ④ `slice(0, VECTOR_TOPK)`；`enrich` 的 SQL **只带** `id IN (…) AND deleted = 0` | 时间窗若另写进 `enrich` SQL ⇒ **同一闸门两份实现**，任一处改动就悄悄不同宽（= 用相似度废掉遗忘曲线），而两份都是「正确代码」、审查看不出来；若先按强度截断再按 cos ⇒ cos 更高但已归档的候选挤掉本该保留的次优项；`enrich` 若带 `embedding` ⇒ 60 × 3KB = 180KB/次的纯搬运 |
| **D4** | `cos` **不取 max**（同一 id 在向量候选集里**至多一条**）；`score` 的合成**只有 `fuseScore` 一处**（缺项记 0、不重算分母）；三路去重收敛在 **`recall.ts`** 一处 | 对 `cos` 取 max ⇒ 造出一个后端从未给过的数，且前提（同一 id 多条）根本不存在；在 `fuseScore` 之外再合成一次 score ⇒ 分数的**唯一出处**破掉（C36）；把去重搬进 `scoring.ts` ⇒ 让它同时承担「打分」与「候选构造」；写第二个合并函数 ⇒ 两份合并语义 |
| **D5** | `vectorUsed` **≡** `routes.vector.ran`（**同一个事实**，实现是 `vectorUsed: pipeline.vector.ran`）；`fromVector` 是 **per-hit**；四种处境（A 不传 / B 传了但整路缺席 / C 跑了没进候选 / D 命中 N 条）**逐格定义** | 给 `vectorUsed` 另立判据 ⇒ 同一个事实两套词（C36），`explain` 与事件可互相矛盾；试图用 `cos` 区分 B/C 行 ⇒ **不可能**（两者在 `cos` 上都表现为 `null`）⇒「缺项」与「真的 0 分」被混成一件事 |
| **D6** | IVF vs flat 比 **`search()` 的命中集合 + 每条 `cos`**（不比桶集、不比 `score`） | 比 `route()` 的桶集是**错命题**（flat 只有哨兵 `'__flat_all__'`，两侧永不可比）；比 `score` 是冗余（`score` 是 `cos` 的确定性函数）且把更强的性质藏起来；不设「**探针吃满 ⇒ 必须完全一致**」这一条 ⇒ 探针边界效应与实现差混在一起，红了也不知道该修哪里 |
| **D7** | `VECTOR_ROUTER='flat'` **且传了**向量 ⇒ **必须产出** `fromVector` / `cos` / `vectorPart`；stage3 那条断言的**口径**改成「`flat` **且不传** ⇒ 不产出」＋新增正控 | flat 不产出 ⇒ **1 万条以下的库永远拿不到那 0.25 权重**（最高分恒 0.75），而「库小所以没有语义能力」在设计稿里**根本不存在**（小库只是慢，不是瞎）；且 **10,000 条会成为「语义能力突然出现」的台阶**（同一查询在 10,001 条时突然多 0.25）⇒ 比性能更坏，且**无法测**（要造两条库） |
| **D8** | `InhibitionTraceOptions` 加**可选** `queryEmbedding?: number[]`（原样透传），并在字段注释写死「必须与那一次 recall 传同一条」 | 不加 ⇒「诊断」与「召回」在传向量时**静默分叉**：`baseScore ≠ Hit.score`，差额 ∈ `[0, SCORE_WEIGHTS.vectorSim]`（0.25），而**没有任何测试会红**（现有测试都不传向量）；若改成「把一致性缩到『两边都不传』」⇒ 等于把「诊断工具在最有用的场景下**故意**给出与生产不一致的数」写成文档条款 |
| **D9** | bench 的召回场景**加 `queryEmbedding` 变体、另立一档**（old-path 一行不删）、**独立一轮重采** | 替换掉 old-path ⇒ **永久丢失**「接线前后整条召回」的对照；删掉「直接调后端」那段 ⇒ **永久丢失**「新增行数来自向量路还是别的」的拆分基准；与接线混在同一次提交/同一轮 ⇒「读数为什么变了」**无法归因**（重采 26 分钟 + ≥5 GB 内存白烧） |

⚠️ **1 条接线后才定清的读法（D1-a）**：D1 的「每次召回都现场装配」指的是
**「每次【带向量的】召回都新造一个端口」**，**不是**「连不传向量的调用也要装」——
装配本身要过一次四态判定，`'auto'` 模式下那是**一次全表 COUNT**
⇒ 若无条件装配，就等于给每一个**根本不需要向量**的既有宿主每次召回加一次全表计数
（sticky 位只救「已过门槛」那一半；小库永远在 `flat_auto` ⇒ **每次都数**）
⇒ **与 D2 的最硬前提正面冲突，而且是测不出来的那种变**。

⇒ 实现取**条件装配**（`MemoryStore.#recallContextOf`：`queryEmbedding === undefined` ⇒ 连 `vector` 这个键都不出现）。
⚠️ **代价（诚实记）**：这条读法让 D1 的字面与实现差一层条件 ⇒ **后人读 D1 必须读到这一行**，
否则会「按字面把它修成无条件装配」，然后 D2 的零影响前提静默破掉。
