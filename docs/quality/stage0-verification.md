### ⚠️ 沙箱环境抖动（**不是项目缺陷**，不判失败）

本机 WorkBuddy 的文件系统 broker 会**随机**拒绝一次文件写入，触发 vitest 的 SSR 转换缓存落盘失败：

```
Error: EPERM: operation not permitted, open '<...>\ssr\<hash>'
 ❯ wrappedPromisesWriteFile .../node-brokered-fs-shim.cjs:724:20
 ❯ Proxy.fetch .../vitest/dist/chunks/resolveConfig.rBxzbVsl.js:6643:7
 Test Files  7 passed (7)      ← 注意是 7，不是 8
 Errors  1 error
```

**根因**（主理人已实测定位）：vitest 的 vite-node 加载 `vitest.config.ts` 时会把**转译后的配置落盘到临时文件**，
而 WorkBuddy 的写入 broker（`tryBrokerFileToken`）会**随机拒绝**该次写入 ⇒ EPERM ⇒ 该次运行少收集一个测试文件。

**已排除的方案**（都试过，均无效或只是碰巧）：`cache: { dir }` 重定向、`cacheDir` 设为项目内、
配置改 `.mjs`、配置改 `.cjs`、TMPDIR/TEMP/TMP 重定向（相对路径与绝对路径都试过）、`cross-env` 包裹。
本次独立复核**也验证了失败率与 TMPDIR 路径形态无关**（相对 `.tmp` / 绝对路径 / 不设，共 15 次采样，红的均为 EPERM 且文件数 < 8）。

> ⇒ **这是沙箱环境问题，不是仓库缺陷**：在用户自己的机器与 GitHub Actions 上没有这个 broker，`pnpm test` 是确定性的。
> ⇒ **不判为源码 Bug，不报为实现缺陷**，按环境抖动记录并重跑。
> ⇒ **跨运行的断言失败数恒为 0** —— 红的每一次都是「文件数变少」，从不是「某条断言失败」。
