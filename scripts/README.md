# CI 契约门禁（阶段 0）

> 把 C25~C37 里**可机械检查**的部分做成脚本，让「文档与代码不一致」在 CI 里当场失败。
> 依据：DESIGN-v2.md §14.3.1（契约清单）/ §5 / §8.4 / §11.2 / §14.3.1 末的跨节锚定表；
> DEVELOPMENT-PLAN.md P0-T06、§7.2。

## 五个门禁脚本

| 脚本                      | 检查什么                                             | 依据                        |
| ------------------------- | ---------------------------------------------------- | --------------------------- |
| `scripts/check-params.ts` | §5 表 ↔ `DEFAULT_PARAMS` **逐键逐值相等**（60 项）    | §5 的 **G26 验收断言**      |

⇒ 脚本里这五行的**路径写死为常量**，不接受配置。

## 阶段 0 的边界

⚠️ 本阶段只做**清单自身**的校验（三列结构 + 五行内容与写死常量一致）。
「动作关键词是否出现在管辖路径的代码块内」需要真实实现文件，
阶段 1 起才有对象可查（届时把 `EXPECTED_ANCHOR_ROWS` 的路径映射到实际文件即可）。

## 新增门禁的做法

1. 在 `scripts/` 下写一个 `check-xxx.ts`，**导出纯函数**（便于单测），CLI 只是薄壳；
2. 在 `package.json` 的 `scripts` 里加 `check:xxx`，并串进 `ci`；
3. 在 `tests/contracts/` 写单测，**必须包含一个反例**（证明它真的能发现不一致）；
4. 在本 README 的对照表里登记。
